## Acceptance Criteria

A checklist used to verify the spec is fully implemented. Written from the
perspective of an end user or tester, not a developer.

**Example:**
```
- [ ] A GET request to `/src/api/orders/index.aspx?access=<valid_token>&sid=<valid_session>`
      returns 200 with the order data JSON.
- [ ] A request with a missing `access` parameter returns 400 with an error JSON body.
- [ ] A request with an invalid `access` value returns 403 with an error JSON body.
- [ ] A request with a missing or invalid `sid` returns 403 with an error JSON body.
- [ ] A non-GET request returns 405 with an error JSON body.
```

Claude can proceed past these during implementation but will flag them when
closing the spec if any remain unresolved.
